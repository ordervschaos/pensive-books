# Many doors, one corridor — making DNA's entry points visible

**Answer up front:** you don't need a new pipeline. The interview is already an
*order-free slot-filler* over eight vision slots — character, world, plot points,
themes, influences, constraints, open questions, notes. Any of them can be the
first thing you fill. What's missing is not capability, it's **affordance**: the
rail offers exactly one button, `START INTERVIEW →`, so the author never learns
the door is wide.

Fix tier 1 = a **starter fork**: replace the single nudge on a fresh book with
4–6 doors, each of which is nothing but a different canned first message plus a
hint about which vision slot to fill first. Zero schema change, zero journey
change. That's the ship.

Fix tier 2 = letting an author who says *"I have a scene"* hand you the scene and
have the machine **ascend** to the logline — you already own that machinery
(`dnaDecompose`, the EPUB import path). Bigger, and separable.

---

## 1. Where this sits

Sub-context: `apps/web/src/features/dna` → the **Idea stage**, first sub-step
(`interview`). Two files own the current impression:

- `lib/dnaJourney.ts` — `stageSubsteps("premise", …)` → `resolveSeq([interview, seed, premise])`.
  `resolveSeq` marks exactly **one** step `now`. This is a gated linear state machine.
- `components/agentRail/journeyContent.ts` — the copy: `NEXT_STEP_MESSAGE`,
  `STEP_NOUN`, `STEP_TEACH`, plus `IDEA_MESSAGE` / `IDEA_TEACH` (the no-idea-yet fork).
- `components/AgentRail.tsx:442-463` — assembles the nudge from those maps.

Note `IDEA_MESSAGE` already **is** a second door. The pattern exists; it's just
been used once.

## 2. Two orders that are being confused

This is the crux, and it's the architectural vocabulary to carry:

| | what it is | may it vary? |
|---|---|---|
| **Derivation order** | idea → foundations → structure → scenes → prose. A dependency DAG: beats can't be causal until acts exist; scenes can't turn a value until the pillar names what's being argued. | **No.** This is the product's whole thesis. |
| **Entry order** | which fact about the book you happen to have first — a face, a hook, a room, a smell. | **Yes, freely.** Nothing downstream cares. |

Right now the UI shows only the derivation order (the journey strip: `1 IDEA ·
2 FOUNDATIONS · 3 STRUCTURE …`), and the author reads it as also being the entry
order. It isn't. **The ladder is how the book is *derived*; the door is how the
author is *met*.**

Everything the doors change is upstream of the ladder — they change what the
agent asks first and which `brief.vision` slot it writes first. The ladder itself
is untouched.

## 3. Why this is nearly free

`BriefVision` (`lib/brief.ts`, rendered by `tree/BriefSection.tsx:129`) is:

```
characters · world_setting · plot_points · themes_aims ·
influences · constraints · open_questions · notes
```

The interview agent's job (`STEP_RECIPE.interview`, `dnaJourney.ts:188`) is to
fill those via `update_vision` after every exchange, and to **converge** —
compile once the core is covered. Slot-filling dialogue is order-independent by
construction: the agent doesn't care whether `characters` or `world_setting`
lands first, only whether the core is covered before it compiles.

So a "door" is a 3-line change:

```ts
// journeyContent.ts
export const START_DOORS = [
  { key: "character", label: "A character",  slot: "characters",
    msg: "I want to start from a character. Ask me about them…" },
  { key: "hook",      label: "A hook",       slot: "plot_points", msg: "…" },
  { key: "scene",     label: "A scene",      slot: "plot_points", msg: "…" },
  { key: "world",     label: "A world",      slot: "world_setting", msg: "…" },
  { key: "feeling",   label: "A feeling",    slot: "themes_aims", msg: "…" },
  { key: "nothing",   label: "Nothing yet — pitch me", slot: null, msg: IDEA_MESSAGE },
];
```

…rendered as a small card grid where the single `START INTERVIEW →` button sits
today, each one just calling the existing `send(msg)`. The agent's interview
recipe already handles all of it; the door merely picks the opening question.

**Design term:** *task-oriented entry points* — you name the user's starting
material, not your internal stage. "A character I can't stop thinking about"
beats "Interview".

## 4. The trap to avoid

Don't promote the doors to top-level navigation next to the journey strip. If
four doors sit beside a strip that always reads `1 IDEA — Interview`, you've
promised branching and delivered a corridor; the author feels lied to on click 2.

Put the fork **inside** the first turn of the interview. The strip stays honest
(`1 IDEA`, one corridor); the doors are how you enter that one room. Once past
the interview, the fork disappears forever — it has no meaning at the beats step.

## 5. The genuine gap (tier 2)

Character-first has an object-permanence problem. If the author starts with a
character, they expect that character to **exist** — a node, with want/need/
wound/lie, visible in the tree. Today it exists only as prose inside
`vision.characters`, and doesn't become a `character` node until the **cast**
sub-step, which is gated on the pillar being accepted (`dnaJourney.ts:132-140`).
Three rungs later.

Two ways out, pick deliberately:

1. **Let the interview mint early foundation nodes** — a character/world_fact
   node authored out of ladder order, marked provisional, reconciled at the cast
   step. Breaks the current gate; needs a "provisional" authoring status so a
   half-known character doesn't tank `contentFill` in `dnaHealth`.
2. **Ascent from a fragment** — the author writes the scene they can't shake;
   you infer logline/premise upward from it. You already have this shape in
   `lib/dnaDecompose.ts` (EPUB → beats → acts → top rungs). Pointing it at one
   fragment instead of a whole manuscript is the smallest real version of
   "start with the scene."

Option 1 is the cheaper truth for character/world doors. Option 2 is the
honest answer for the scene door specifically.

**Recommendation:** ship the fork (§3) first and watch which door people pick. If
"a character" and "a scene" dominate, that's the evidence to spend on §5.

## 6. Success criteria

- A fresh book's rail shows ≥4 named starting materials, not one verb.
- Picking any door lands the author in the same interview and compiles the same
  vision; the journey strip never contradicts the door.
- No change to `resolveSeq`, `stageComplete`, or the edge twin
  (`_shared/dna-journey.ts`) — if a door needs a journey change, it's tier 2 and
  should be scheduled, not smuggled.
