# Driving a short story down the Novel DNA ladder — headless, no UI

**Task:** generate a *complete* short story through the DNA pipeline without touching the web app —
every rung filled in (premise → foundations → structure → scenes → prose), plus **meters, threads,
characters, and evals**. Book **1275**, "the goodbye machine."

---

## 1 · Where this sits (the subcontext)

The web app (`apps/web/src/features/dna`) is the **authoring surface**. Under it is a **substrate**:
the whole book is one self-similar tree of `book_nodes` — the **genotype**. The reader never sees the
tree; a projection (`reconcileDna`) transcribes it into `pages` — the **phenotype**. (This
genotype/phenotype split is the load-bearing metaphor: *content* lives in the tree, the *rendered
artifact* is downstream and disposable.)

"Without the UI" means: drive the substrate directly. Two engines exist for that —

| Engine | What it is | Cost | Fidelity |
|---|---|---|---|
| **Real edge fns** (`dna-expand` + client `expandNode`) | prod path, routes AI to DeepSeek/OpenRouter | $ per book | exact |
| **The bridge** (`scripts/eval-bridge.mjs` → `runDnaExpand`) | reimplements the engine, routes AI to a free headless `claude -p` | free | ~90% mirror |

I used **the bridge**, because it runs fully headless and writes prose directly. The real client
path needs a browser (the Supabase browser client + a `/api/stream-prose` proxy for off-worker prose
streaming), which is heavy to stand up in Node. Trade-off surfaced: the bridge is *not* a perfect
mirror — it lacks the `contract` brief-compile and the game-twin reconcile, so I **filled those gaps
by hand** in the driver (see §4).

## 2 · The system — stakeholders, parts, seams

```
          ┌─────────────────── the driver (scripts/dna-short-story.mjs) ───────────────────┐
 BRIEF ─► │ seed → premise → pillar → [cast · world · relationships · set-pieces · voice ·  │
(human)   │                            games] → METERS → acts → threads → BEAT SHEET →       │
          │                            scenes → PROSE                                        │
          └───────────────┬───────────────────────────────────────────────────┬────────────┘
                          │ each rung = one runDnaExpand() call (claude -p)     │
                          ▼                                                     ▼
                  book_nodes (Supabase, service role)  ◄──── the eval reads it back
                          ▲                                                     │
                          │                                        scripts/dna-short-story-eval.mts
                          └──────── genotype (private) ── seam ── pages (phenotype, not built here)
```

- **Author (human):** supplies only the **brief** + the one hand-authored **logline** (the seed).
- **Architect (AI, per rung):** each `runDnaExpand` call is a story architect expanding one node into
  the next resolution down — *dead-reckoning* (it commits, it doesn't second-guess).
- **Editor (AI/engine, after):** the eval is the **sensing half** — real lints + an observed-meter
  read + an editor's-read. This generate↔verify duality is the spine of the method.

**The ladder is a typed sequence** (`LADDER_KINDS`): order is real information — each rung is *higher
resolution, lower authority over causality*. Causality is settled high (in the beat sheet); scenes
and prose only **realize** it, never re-invent it.

## 3 · What each rung produced (book 1275)

- **Seed → Premise:** the logline became a *priced dramatic question* + a 5-movement emotional shape
  ("Comfort into unravelling").
- **Pillar (the controlling idea + the ending):** *"Grief is not a wound to be closed but a question
  you keep asking the dead until you realise you were always the one answering."* The ending is
  pre-committed — the tree is built backward from it.
- **Cast (4):** each with **want / need / wound / lie / idiolect**. Miriam's lie: *"grief is a wound
  that closes if you apply the right procedure."* (The lie is the inner-arc engine.)
- **World (5 facts):** *operable* rules — each has a mechanism, so the climax's turn can **fire** a
  rule rather than invent one (the anti-*deus-ex-machina* invariant).
- **Relationships (4 dyads):** bond + current charge.
- **Set-pieces / Tentpoles (5):** the must-happen moments — concrete scene-images, genre-specific
  enough that omitting one is a broken promise. Each gets **placed** on exactly one beat later.
- **Voice profile (1):** the operable prose signature injected into every prose call.
- **Games (3):** *The Audit · The Séance · The Goodbye* — each a **contest** with explicit
  **win/lose CRITERIA** (not stakes): the states the story must establish before a resolution can
  fire. This is the "possibility space" model — you can't win if you can't lose.
- **Meters (5):** 3 **game-score** meters (twin of each game) + 2 **shape** meters (`dread` tension,
  `the question` mystery) each carrying a **target curve**.
- **Acts (4):** turning points targeted at ≈25/50/75/90% — the **structural-gravity** marks.
- **Threads (9):** the **promise registry** — open loops (6 authored + 3 game-resolution twins).
- **Beat sheet (10 beats):** one **global causal pass** — mints `needs`/`establishes` state keys
  forming a **DAG**, places every tentpole, schedules thread setup→payoff, plans polarity to oscillate.
- **Scenes (22):** each beat projected into 1–3 scenes that **realize** it (inherit polarity, threads,
  causal keys) — a local pass, causality already settled above.
- **Prose:** every scene, streamed off the beat plan with a rolling continuity digest.

## 4 · Two gaps I had to fill (bridge ≠ mirror)

1. **Meters.** In prod, non-game meters ride a `contract` brief-compile the bridge doesn't implement,
   and each game's *game-score* meter is minted by `reconcileGameTwins`. I replicated the pure
   `gameTwins()` shape (a `game_score` meter + a `setup_payoff` resolution thread per game) and minted
   two shape meters with explicit target curves — so the `target_drift` lint can actually bite.
2. **The ESM hoisting bug (worth remembering).** My driver reuses helpers from `dna-flow-test.mjs`.
   A **static** `import` is *hoisted*: the imported module fully evaluates **before** my file's
   top-level `process.env.DNA_NO_MAIN = "1"` runs — so flow-test's own `main()` fired on import and a
   *second, unrelated* story flow started concurrently. Fix: a **dynamic** `await import(...)` runs at
   call time, after the env guard is set. (Lesson: env-flag guards + static imports don't compose.)

## 5 · The eval (the sensing half) — real engine, headless

`scripts/dna-short-story-eval.mts` runs the app's **own** `novelDna.ts` under `tsx` against the live
tree — not a reimplementation. Four instruments:

1. **`validate()`** — structural / promise / causal / vertical lints.
2. **`openObligations()` + `debtSettled()`** — debt-based completion (every promise a reader is owed).
3. **`analysisText()`** — pacing vs target · promise ledger · topography · causality DAG · meters.
4. **Observed meter trace** (bridge `read-meters`) — rates what the *prose* delivers, then diffs it
   against each meter's target curve. (Runs only after prose exists.)

**Structural grade (pre-prose):**
- **Pacing near-perfect:** turns at 27 / 50 / 77 / 100% vs targets 25 / 50 / 75 / 90%.
- **Closed causal DAG:** every beat's `needs` earned by an earlier `establishes` — no `uncaused_therefore`.
- **All 6 registry threads: setups = payoffs = 1** (no dangling promises).
- **11 warnings the engine caught by itself** — the interesting part, because they're *real*:
  - `dead_arc` ×4 — characters carry a **lie** but no thread schedules the inner arc (invisible to the plan).
  - `static_relationship` ×4 — dyads declare a charge no scene advances.
  - `sagging_middle` — 4 down-polarity scenes in a row (visible in topography `-+---+-++---+----++---`).
  - `shape_unmapped` — premise promised **5** movements, structure has **4** acts.
  - `logline_static` — the logline is passive (things happen *to* Miriam).

These are exactly the fixes a human editor would do next — the engine *found its own weak links*.

## 6 · How to reproduce

```bash
# 1. Build the full structural tree (no prose) — fresh book
node scripts/dna-short-story.mjs                    # → book id in scripts/.dna-short.log

# 2. Write prose for every scene (resumable, idempotent)
DNA_PROSE_ONLY=1 DNA_BOOK_ID=<id> node scripts/dna-short-story.mjs

# 3. Grade it (real lints + observed meters + manuscript assembly)
cd apps/web && node --import tsx ../../scripts/dna-short-story-eval.mts <id>
```

Reference: the pipeline is documented rung-by-rung in `docs/dna/00-pipeline-overview.md` and the
per-rung deep dives (`01`–`06`). The engine is `apps/web/src/features/dna/lib/novelDna.ts`
(`validate`, `analysisText`, `gameTwins`, `obligationLedger`).
