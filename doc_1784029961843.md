# The Frontier Engine — options, not a single next step

*Design doc, 2026-07-14. Grounds the "agent should see its options" conversation in the
current code (`dnaJourney.ts` / `_shared/dna-journey.ts` / `book-agent/context.ts`).*

## 1. Where this sits

The **guidance layer** of the DNA studio: the pure code that looks at the tree and answers
"what can advance this book right now?" Today that layer is `currentObjective()` — it is
consumed in exactly two places:

- **Agent**: injected as `<current_objective>` into `book-agent`'s system prompt
  (`context.ts:282`, three-state injection).
- **User**: the "Next" nudge button in `AgentRail.tsx:372` (one card, one message).

So one function already sits at the chokepoint. The change is to what it computes, not
where it plugs in.

## 2. The diagnosis (what's structurally wrong today)

`currentObjective` is a **serial scheduler**: `buildJourney` gates stages in order,
`stageSubsteps` walks a serial list and crowns the *first* incomplete required step
"now", `STEP_RECIPE` attaches instructions. Everything else is invisible:

1. **Options are collapsed.** `stageSubsteps` already computes `"available"` statuses
   (parallel branches: world, games, tent-poles, relationships) — but only `"now"`
   survives into the objective. The agent and the user both see one card.
2. **Coverage-chain blindness — the "prose is complete" bug.** `stageComplete` gates are
   count-based at the layer level:
   - `scenes: scenes.length >= 1` — ONE scene anywhere completes the stage.
   - `draft: scenes.every(sceneDrafted)` — all *existing* scenes prosed.
   A beat with zero scenes is invisible to both gates: the journey can report "done"
   while Act 2 has three unexpanded beats. `stageProgress` *already computes* exactly
   this gap (`beatsWithScenes/beats.length`, `gapLabel`) — but `stageComplete` never
   reads it. The signal exists; it isn't wired into the done-gates.
3. **The open-ended axis has no representation.** Pillar depth (more world facts, more
   relationships, richer meters) isn't a step you finish — it's a dial: **cost =
   context tokens on every downstream generation, value = coherence**. A serial ladder
   can't express a dial; a move with a cost/value annotation can.
4. **The agent's two jobs are conflated.** "Fulfill the user's objective" vs "drive the
   book to completion" are different *policies*, but today both ride the same
   single-anchor prompt — the three-state injection in `context.ts:229` is a patch over
   this missing distinction.

## 3. The design — mechanism/policy split

**Architectural move: separate the *mechanism* (what moves exist) from the *policy*
(which to take).** This is the classic mechanism-vs-policy separation; the frontier is
the open list, the modes are search policies over it.

### 3.1 `frontier(nodes, brief, settings): Move[]` — the mechanism

A pure function, twinned like `currentObjective` is today (web `dnaJourney.ts` +
`_shared/dna-journey.ts`, parity-locked). One typed record per legal advancing move:

```ts
interface Move {
  id: string;                 // stable: `${type}:${target}` — diffable across renders
  type: "fill"                // a required field on an existing node is blank
      | "add"                 // a child collection can grow (cast, world, threads)
      | "expand"              // an engine pass: propose_expansion target on a node
      | "prose"               // render one scene
      | "settle"              // pay/waive an open obligation
      | "deepen"              // optional enrichment (the pillar dial)
      | "repair"              // a lint with a known fix shape
      | "handoff";            // render/publish — author-only gestures
  target: { nodeId?: string; kind: NodeKind };
  label: string;              // "Break Beat 7 (Act 2) into scenes"
  required: boolean;          // on the critical path to a complete book?
  ready: boolean;             // prerequisites met (false = locked, shown greyed)
  actor: "agent" | "author" | "either";
  cost: "free" | "engine" | "render";     // rough $ / context weight
  value?: string;             // one line: why this move matters (the coherence story)
  recipe?: string;            // the STEP_RECIPE text, now per-move
}
```

Emitters — each already has its signal computed somewhere, this just stops discarding it:

| Emitter | Source today | Moves it yields |
|---|---|---|
| Coverage chain | `stageProgress` (act→beats, beat→scenes, scene→prose) | one `expand` per uncovered act/beat; one `prose` per undrafted scene (ordered) — **fixes bug #2**: required moves per node, not a layer tally |
| Required fields | `dnaSchema.requiredKeys` + `contentCompleteness` | `fill` per blank required field |
| Serial ladder | `stageSubsteps` required steps | `expand`/`add` for seed→premise→pillar→contract→cast→acts→beats |
| Optional branches | `stageSubsteps` `optional` items | `deepen` moves, `required: false`, cost/value annotated |
| Obligation ledger | `openObligations` | `settle` per open promise (endgame-gated as now) |
| Lints | `validate()` | `repair` for the fixable subset |
| Render seam | `renderBlockers` clear + drafted | `handoff` (actor: author) |

**Completion is redefined as frontier emptiness**: the book is done when zero
`required` moves remain — the debt-based idea (`debtSettled`) generalized to the whole
tree. No more count-based gates to keep honest.

### 3.2 Policy layer — the two modes become explicit

```ts
rank(moves, mode): Move[]   // policy: order + prune
```

- **Mode B — drive to completion** (guided flow, auto/∞ mode): rank required+ready
  moves by reading order / stage order; the top move rendered with its recipe *is*
  today's `currentObjective` — the current behavior falls out as the special case
  `rank(frontier)[0]`. Auto mode consumes the ranked list as a work queue.
- **Mode A — fulfill the user's objective**: the user's message is the anchor; the
  frontier is injected as *context* (`<available_moves>`), not as an instruction. The
  agent knows what's legal without being pushed. This replaces the three-state
  injection heuristics with a structural answer.

### 3.3 Surfaces

- **Agent prompt**: `<available_moves>` block (compact, one line per move, required
  first, deepen moves with their cost/value line). `<current_objective>` stays for
  mode B as the ranked head. The agent can finally say "your options are…" truthfully.
- **AgentRail "Next" card → options list**: render the top N ranked moves as buttons;
  clicking sends that move's recipe as the message (same `send(..., {isNextStep})`
  path). The author sees the same frontier the agent does — one source of truth.
- **Dev inspectability**: the frontier is a pure function of the tree, so (1) unit
  tests enumerate expected moves for fixture trees; (2) a dev pane — a `frontier` view
  on `DnaJsonPage` or an Analytics-tab section — shows the live `Move[]` JSON with
  required/ready flags; (3) optionally stamp the frontier snapshot the agent actually
  received into `book_agent_runs` (next to `groundingLabels`) so any turn can be
  audited: *what did the engine believe the options were when it acted?*

## 4. Migration path (each step shippable alone)

1. **Phase 1 — mechanism, read-only.** `frontier()` in `dnaJourney.ts` + twin + parity
   lock + tests + dev pane. Zero behavior change; you can eyeball it against real books.
2. **Phase 2 — objective rides the frontier.** `currentObjective` = render of
   `rank(frontier)[0]`; delete the parallel bookkeeping in `stageComplete` /
   `nextDraftTarget` that the emitters subsume. Coverage bug dies here.
3. **Phase 3 — surfaces.** `<available_moves>` injection + mode A/B split in
   `context.ts`; options list replacing the single Next card in `AgentRail`.

## 5. Named concepts in play

- **Frontier / open list** (search): the set of expandable next states — here, moves.
- **Affordance**: an action the environment makes available; a `Move` is a typed affordance.
- **Mechanism vs policy**: enumerate what's possible (pure, testable) separately from
  choosing (rankable, modal). The core maintainability win.
- **Anchor, not fence**: existing agent-context principle — frontier-as-context extends it.
- **Coverage chain**: every act → beats → scenes → prose; completeness is chain
  coverage, not layer counts.
- **Done-gate / debt-based completion**: `frontier.filter(required).length === 0`
  generalizes `debtSettled`.
- **Work queue**: auto mode consuming ranked required moves.
