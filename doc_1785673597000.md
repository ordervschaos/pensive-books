# Redesign: empty nodes instead of nil ghosts

**The change in one line:** move "this doesn't exist yet" out of the *shape* of the tree and
into a *value* on the tree — so every slot in the book has a stable id you can type into,
point an agent at, or start from.

---

## 1. Where this sits

Upstream of everything. It changes what a `book_nodes` tree *is* between "book created" and
"book finished." Today the tree is **sparse**: only generated nodes exist, and the missing
ones are painted in by `lib/dnaSkeleton.ts` as read-only ghost rows (`GhostRows.tsx`,
`"not yet generated"`). After this, the tree is **dense**: every slot the structure template
knows about is a real row with `content: {}`.

Nothing above (the `books` row) or below (the `pages` projection) changes. This is entirely
inside the DNA seam.

## 2. What it is, plainly

Two representations of absence:

| | today (sparse) | proposed (dense) |
|---|---|---|
| "Act 2 doesn't exist" | there is no row | there is a row, `content: {}` |
| absence is encoded in | the **shape** of the data | a **value** on the data |
| can you click it? | no | yes |
| can the agent target it? | no — it must `create` | yes — it `update`s a known id |
| can you start in the middle? | no | yes |
| who must know about emptiness? | nobody | **every read path** |

That last row is the whole cost of the change. Everything else is upside.

The pattern name is the **Null Object pattern** (an object that satisfies the interface but
means "nothing") applied to a tree, plus **eager materialization** of what is currently a
lazily-derived projection.

## 3. Why it matters

Because the current design has a hard rule baked into `dnaSkeleton.ts`:

> *"A rung ghosts ONLY while it is entirely empty; the moment any real node lands there its
> ghost is gone for good."*

That is all-or-nothing per rung, and it is exactly the constraint that forbids the thing you
want. Write one act and the other two ghosts vanish. Write a character and the whole cast
preview disappears. The tool assumes you fill a rung in one shot, top-down, in order — which
assumes a **plot-first author**. Every other door is closed.

Dense empties open all six doors, because "starting from a character" is just *filling one
node whose siblings and ancestors happen to be empty.* No new mode, no new subsystem.

## 4. The system

### 4a. Fill is a fold, not a flag

Your definition — "emptiness is measured by complete emptiness of children" — needs two
amendments:

**(a) own content counts too.** An act with a `turning_point` but no beats is not empty.

```
empty(n) = ownEmpty(n) && children(n).every(empty)
```

**(b) you need a third state.** Empty vs non-empty can't distinguish these two:

```
ACT  Confrontation      ← nothing here, nothing below      = EMPTY
ACT  Confrontation      ← nothing here, but a beat below   = STUB
  BEAT  the betrayal        is written
```

`STUB` is *literally the multi-entry case*. It is the signal that says **"a parent is owed
here — run ascent."** If you collapse it into "non-empty" you lose the trigger for the entire
six-doors feature. Keep it.

So: two orthogonal axes, computed in one post-order fold (O(N), ~6 levels deep, memoized into
a `Map<id, Fill>` at tree-load — **never per React row**, that's O(N²) on re-render):

```
own      : empty | partial | complete     ← already exists: dnaSchema.contentCompleteness()
subtree  : 0.0 … 1.0 fill ratio           ← new: the rollup
```

`isEmptySubtree(n) = own === "empty" && subtree === 0`.

Bonus you get for free: that same rollup **is** a progress meter. "This book is 40% scaffolded,
9% written" falls out of the denominator, and slots straight into `JourneyStrip` and
`dnaHealth` — which currently hand-count completeness in their own way.

### 4b. Where the template text lives (the load-bearing detail)

If you materialize the beat "The Hook" with `content.title = "The Hook"`, it is **filled the
moment it is born** and the whole fold reads garbage.

So: template text never touches `content`.

```ts
node.content   = {}                                          // the author's / agent's plane
node.authoring.scaffold = { title: "The Hook", hint: "…", slot: "hook" }   // the template's plane
```

`ownEmpty` reads `content` only ⇒ blank means blank, no per-field provenance needed. The UI
renders `scaffold.title` in placeholder styling; the first real write goes to `content.title`
and flips the state. "Reset this node" becomes `content = {}` — the scaffold survives.

Free win: `scaffold.slot` carries the slot identity the existing `slot_*` lints
(`slot_unmapped`, `slot_misplaced`) currently have to *infer by position*.

One more exclusion: the `OUTPUT_FIELDS` list (`novelDna.ts:425` — `observed_*`, `prose`,
`confusion_flags`…) must not count as fill either, or a read pass would "fill" an empty node
with its own verdict about nothing.

### 4c. Two directions of inference

Materializing empties makes multi-entry *possible in the UI*. It does not make it work — the
generation side still only runs downhill.

```
        DESCENT (deductive)              ASCENT (inductive)
        parent constrains child          children imply parent
        lib/dnaExpand.ts   ✅ exists     lib/dnaDecompose.ts  ✅ exists (prose→beats→acts only)
```

**The six doors are already built — they're `dna-decompose` generalized.** Today ascent runs
exactly once, from imported epub prose. Generalize it to *"given filled nodes at rung K,
induce rung K−1"* and every door opens with no new pipeline:

| door | filled first | ascent path |
|---|---|---|
| character | `character.wound/lie` | → pillar.controlling_idea → premise → logline |
| world | `world_fact` / `location` | → pillar → premise |
| situation ("what if") | a `beat` | → act → premise |
| voice / image | `voice_profile` | → premise.tone → pillar |
| theme | `pillar.controlling_idea` | (already at the pillar — descend) |
| plot | the brief | the current path |

The right mental model for the whole engine stops being **pipeline** and becomes
**constraint propagation over a partially-filled tree** — closest familiar analogue is
Hindley–Milner type inference: author-filled nodes are *annotations* (fixed points), empty
nodes are *inferred*, and a filled child under a contradicting filled parent is a *unification
error* (a lint, not a crash).

Consequence worth naming: **you never ask the author which door they walked in.** The first
non-empty node *is* the door. Six labeled entry buttons are fine as an affordance, but they
are "create + focus this node," not modes.

### 4d. The picture

```
                          ┌──────────────────────────┐
   BRIEF  ───────────────▶│         SEED             │  ← door: plot
                          └────────────┬─────────────┘
                                       │
                          ┌────────────▼─────────────┐
                          │        PREMISE           │  ← door: theme
                          └────────────┬─────────────┘
                                       │
                          ┌────────────▼─────────────┐
              ascent ▲    │        PILLAR            │    ▼ descent
             (induce) │   └──┬──────────────┬────────┘    │ (expand)
                      │      │              │             │
                 ┌────┴──────▼───┐    ┌─────▼──────┐      │
   door: char ──▶│  CHARACTER    │    │    ACT     │      │
   door: world ─▶│  WORLD_FACT   │    └─────┬──────┘      │
   door: voice ─▶│  VOICE        │          │             │
                 └───────────────┘    ┌─────▼──────┐      │
                                      │    BEAT    │◀─────┴── door: situation
                                      └─────┬──────┘
                                            │  (scenes stay derived — not materialized)
                                      ┌─────▼──────┐
                                      │   SCENE    │
                                      └────────────┘

   fill states:   ░ empty   ▒ stub (empty, something below)   █ filled
   the agent's job = find the frontier between ░ and █, then ascend above / descend below.
```

**Materialization depth stops at BEAT.** The structure template knows how many acts and which
slotted beats; it does *not* know how many scenes a beat needs. Rule: *materialize exactly as
deep as the template knows the shape.* Scenes stay derived-on-expand.

## 5. What breaks — the honest list

Sparse-absence can't be read wrong; dense-absence **fails open by default**. Every consumer
that iterates nodes now sees empties, and a missed filter is a silent wrong answer:

1. **`renderPages` / `reconcileDna`** — empty beats become blank pages in the reader.
2. **`dnaExpand` prompt context** — the model imitates the blankness. **See §5a — this is the
   one worth reading; the token-cost fear is a red herring and the semantic risk is worse than
   it looks.**
3. **Lints** — `missing_field` fires on every placeholder. (Inverse is the useful new lint:
   `orphan_fill` = filled child under an empty parent ⇒ ascent is owed.)
4. **Obligation ledger / causality DAG / threads** — empty beats produce and consume nothing;
   a `therefore` chain must not "break" across them.
5. **`dnaHealth` / meters** — denominators shift. (Actually an improvement, see 4a.)
6. **Realtime + `book_tree_versions`** — ~100–200 extra rows per book on the wire and in every
   snapshot. You already paid for REPLICA-FULL amplification once; measure before assuming fine.
7. **Staleness (`src_hash`)** — an empty node has no input set. Don't hash it, don't stale it.

### 5a. The prompt-context risk, in detail

**Correction to an earlier draft of this doc: the figure is ~16 stubs, not 200.** The
stop-at-BEAT rule (§4c) excludes scenes, and scenes are the only place a number like 200 comes
from. Weiland 3-act materializes 3 acts + 9 slotted beats + 2 cast + premise + pillar = **16
rows** (`novelDna.ts:2083`). A few hundred tokens. **The token-cost half of this risk is not
real.** The semantic half is, and it is worse than "the model imitates blankness."

**Why it bites.** `supabase/functions/dna-expand/index.ts:349–420` is not a tree dump — it is 8
hand-built registry blocks (cast/world · threads · acts · tentpoles · world rules · locations ·
…), each guarded identically:

```ts
const entityBlock = entities.length ? "CAST & WORLD (reference characters BY NAME):\n" + … : "";
```

Sparse ⇒ `length === 0` ⇒ block omitted. Dense ⇒ `length === 2` ⇒ the guard flips true and emits:

```
CAST & WORLD (reference characters BY NAME):
-  [?] {}
-  [?] {}
```

**The guards test presence, and materialization makes presence meaningless.** One bug, eight times.

Three distinct harms in that one line:

1. **Nameless anchor** — the header instructs "reference BY NAME" and then supplies no name.
2. **Asserted absence** — `{}` reads as *"this character has no want, no wound, no lie"*: a fact,
   not "unknown." Models treat supplied structure as ground truth.
3. **Few-shot poisoning** — the block is implicitly a format exemplar. Half-empty exemplars lower
   the model's fill rate **on the filled nodes too**. This is the insidious one: it degrades
   output everywhere, not only where the stubs are.

**The fix — at the bindings, not per block.** ⚠️ **Amended during implementation.** The draft above said
"one line: `const nodes = liveNodes(rawNodes)`". That is *wrong* and would have broken generation. `nodes`
feeds `byId`, and `byId` walks the ancestor chain — but **the target of a generation call is by definition
the empty node being filled**, so a live-filtered `byId` loses it and the walk terminates early, silently
dropping every ancestor constraint. The correct shape is **two named views**:

```ts
const byId = new Map(nodes.map((n) => [n.id, n]));  // STRUCTURAL — raw, for walking shape
const live = liveNodes(nodes);                      // READ — everything shown to the model
```

Registries bind off `live`; `byId`/ancestry stay raw. Every `.length` guard then behaves exactly as today. **Pin it with a golden
test**: feed a materialized skeleton in, assert the emitted prompt is byte-identical to the
sparse-tree prompt. That is the real net — it catches every block added later, which per-block
filtering never would.

*Shipped as* `apps/web/src/features/dna/lib/dnaContext.golden.test.ts`. To make the blocks reachable from a
test at all, they were **moved** (not copied — a copy is the drift this repo keeps paying for) out of
`dna-expand/index.ts` into `supabase/functions/_shared/dna-context.ts`. The arrays stayed at the call site,
so all downstream uses (`threads` alone has 36) were untouched; only the pure renderers moved.

**⚠️ Amended during implementation: there are THREE consumer classes, not two.** The draft below split
consumers into "entity registries (omit)" and "ladder sequences (mark)". Wiring `book-agent` surfaced a
third that neither rule fits — and getting it wrong would have broken the agent outright:

| class | consumers | rule | why |
|---|---|---|---|
| **1. Readers** | generation prompts, render, digest, lints, ledger, verify | **omit** empties (`liveNodes`) | a nameless row is worse than no row |
| **2. Sequences** | the arc, sibling-beat plan | **keep + mark** (`— NOT YET WRITTEN`) | position is information; drop them and Act 2 reads as the whole book |
| **3. Workers** | the agent's tree digest, the tree editor | **keep + collapse** | placeholders are the *work queue* — the agent fills a slot by targeting its id, so hiding them removes its ability to act at all |

Class 3 is why "route everything through `liveNodes`" is the wrong slogan. For the agent the fix isn't
filtering but **compression**: an `empty` state already means the whole subtree is empty, so keep the topmost
empty node, drop its descendants, and fold consecutive empty siblings into one line with every id intact
(`[b2, b3, b4] L2 beat 2–4 ×3: EMPTY — …`). Shipped as `treeDigestLines()` in `_shared/dna-context.ts`.

*Numbering trap, worth its own line:* the digest's beat/scene numbers must keep being computed over the
**full** node list, blanks included. "beat 7" has to denote the same node to the agent, the tree UI, and the
render — numbering off the collapsed list silently renumbers the book. There's a test for it.

**Refinement — blanket-omit is wrong for the ladder.** If the author wrote only Act 2 and you
strip Acts 1 and 3, the model writes Act 2 *as if it were the whole book* — breaking exactly the
use case this redesign exists for. So the rule is per-block, on a predicate that already exists
(`isEntityKind()`):

| block family | rule | why |
|---|---|---|
| entity kinds — cast, world rules, locations, threads, tentpoles | **omit** empties | BY-NAME lookups; a nameless row is strictly worse than no row |
| ladder kinds — acts, beats | **keep, marked**: `- [Setup] — NOT YET WRITTEN (25% of book: hook · inciting · first plot point)` | position is information; ~20 tokens buys "you are writing the middle of a three-act book" |

Under either rule: **never `JSON.stringify` an empty content object.** `{}` is the most
blankness-imitating token sequence available.

**Partials are already safe.** `JSON.stringify({name:"Mira"})` omits absent keys, so a
half-filled character degrades gracefully on its own. The damage is confined to *fully* empty
nodes — which is what makes the one-line fix sufficient.

**Principle worth carrying:** *don't ask the model to filter what you can filter.* An instruction
like "ignore empty entries" costs tokens and works probabilistically; removing them is
deterministic.

### 5a-bis. Emptiness is HUNGER — the second channel

⚠️ **Owner correction, folded in after P1.** The rules above are all about *suppression*, and taken alone
they're wrong in spirit: **the empty structure represents hunger.** We *want* those slots filled. A design
that only knows how to hide them quietly tells every consumer the book is finished.

The resolution: the danger was never that a model **sees** emptiness — it's that it **misreads** emptiness
as a settled fact. Placement decides which:

```
- Mara [protagonist] {"name":"Mara","want":"to belong"}
- [?] {}                         ← inline among content: "this character HAS no want"   = a claim. poison.

UNFILLED: 2 cast slots · acts 1 & 3 · 9 beats
                                 ← its own named channel: "these are waiting for you"   = an invitation. fuel.
```

Same fact, opposite effect. So the rule is not "hide" but **two channels**:

> **Omit empties from the CONTENT blocks. State the hunger once, explicitly, in its own voice.**

Evidence this is the right generalization: the `— NOT YET WRITTEN` marking on acts (§5a) *is* a hunger
channel — invented locally for one block because dropping empty acts made a book look finished at Act 2.
That is the same problem everywhere. It deserves a mechanism, not a special case.

**Who gets the hunger channel — only consumers that can ACT on it:**

| consumer | hunger? | form |
|---|---|---|
| tree editor | **yes** — hunger *is* the UI | the placeholder rows themselves (the point of the redesign) |
| agent | **yes** — hunger is its work queue | per-node, collapsed (`treeDigestLines`) |
| generation prompts | **yes**, aggregated | one line: "38 beats still unwritten after this" — stops a scene generator wrapping the book up early. Never inline rows, which would invite it to fill what it wasn't asked for |
| renderer | **never** | a reader must not see "Chapter 4: yet to be filled" |
| lints | **never as errors** | hunger is not a defect; a book that lints red for existing is unusable. Belongs in the completeness meter — `fillRatio()` (P0, currently unused) is already exactly that |

**Change to make:** one `hungerBlock(nodes)` in `_shared/dna-context.ts`, generalizing the ad-hoc act
marking; wired to the agent digest and generation, never to the renderer, never as a lint.

**The reframe worth keeping:** emptiness stops being the *absence* of a node and becomes **the tree's
appetite** — first-class and queryable. That is what makes start-anywhere work: the frontier between filled
and empty is precisely what the agent should steer toward, and `fillRatio` turns it into a progress bar for
free.

### 5b. The chokepoint

**Pay this once, at a chokepoint — not seven times.** Add to `novelDna` (both twins,
parity-locked):

```ts
liveNodes(nodes: DnaNode[]): DnaNode[]   // strips empty subtrees
```

and make every read path consume that instead of the raw array. The **tree editor is the only
consumer allowed to read raw**. Same discipline as `lib/stopRun.ts` and the fail-closed
`validateOps` boundary — you've done this exact move before and it worked.

## 6. Materialize once, not continuously

If placeholders are real rows, deleting one must *stick* — otherwise a reconciler re-adds it
and the author is fighting the tool. So the materializer is **one-shot, not a daemon**:

- runs at book creation, and on an explicit `pillar.structure` change (as a reviewable proposal)
- idempotent, keyed on `scaffold.slot`
- never runs in the background

The tree is author-owned after the first pass. `dnaSkeleton.ts` isn't deleted — it is
**promoted from renderer to seeder**: its `GhostItem[]` become `newNode()` rows (which already
mint `content: {}, status: "empty"` — `novelDna.ts:2485`). Backfill for existing books is the
same function run once.

## 7. Phasing (recommended order)

| | what | risk |
|---|---|---|
| **P0** | `fill` fold in `novelDna` + twin + parity test: `ownFill`, `subtreeFill`, `fillMap`, `liveNodes` | none — pure, no behavior change |
| **P1** | route every read path through `liveNodes` (incl. `dna-expand/index.ts:349`) + the golden prompt test of §5a; entity-omit / ladder-outline split | none — tree still sparse, so `liveNodes` is identity |
| **P2** | materializer + `scaffold` slot; `GhostRows` becomes a *style* of `TreeRow`, not a component | tree goes dense — P1 is the net |
| **P3** | generalize `dnaDecompose` → `induce(rung)`; agent gets `ascend` beside `propose_expansion`; "next move" becomes frontier-driven | real work |
| **P4** | six entry buttons on an empty book | cosmetic |

P0 and P1 are the safety net, and they go in **before** the thing they protect against. That
ordering is the recommendation, not a formality.

## 8. Reference

- **Null Object pattern** — Woolf, *Pattern Languages of Program Design 3* (1997). Absence as a
  first-class object with the same interface, so callers stop branching on `null`.
- **Hindley–Milner inference** — the bidirectional model: annotations are fixed, everything
  else is inferred, conflicts are unification errors. Exactly the shape of "author-filled
  nodes constrain, the agent solves the rest."
- **Tolkien vs. King** — the two extreme doors. Tolkien built Middle-earth's languages for
  years before *The Hobbit* had a plot (world-first). King's *On Writing* (2000) rejects
  plot-first outright and starts from a situation — "what if a town were cut off under a
  dome?" — then drops characters in. Your tree has to seat both at the same table.

2. ~~**Delete-a-placeholder semantics**~~ — **RESOLVED 2026-08-02 (owner): yes.** Deleting an empty slot is
   an authorial statement and suppresses the lint. Shipped as a tombstone: `pillar.authoring.waived_slots`
   (a slot-key list). It lives on the **authoring** plane, not content, for the same reason `scaffold` does —
   it is a fact about authorship, not about the story, and in `content` it would make a pillar read as
   *filled* the moment somebody declined a slot. `structureLints` skips `slot_missing` for waived keys and
   `seedSkeleton` never re-mints them. The delete confirm names the consequence, because "delete" and
   "decline permanently" are different promises.
