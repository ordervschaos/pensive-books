# Novel DNA — the complete structure

**Status:** the authoritative **data contract**. `novel-dna-spec.md` says how to build/store/render it;
this doc defines *what it is* — every node, every field, exhaustively.

## The invariants

1. **The DNA is the book.** `render(DNA)` is a pure function — there is no book content anywhere else.
   Pages, chapters, word counts are *projections*, never stored (§6).
2. **The structure is hungry.** It is a fixed set of typed slots waiting to be filled. Filling the
   load-bearing slots is the author's job; the rest the AI generates. The UI exists only to get this
   structure filled — in the most meaningful order (§8).
3. **Filled = renderable.** When the slots required for render (§7) are filled and accepted, the book
   exists. Completeness is a checkable predicate, not a feeling.

### Fill-source legend (used in every table)

| mark | meaning |
|---|---|
| ★ | **human core** — the AI genuinely can't guess this; the author must supply it |
| U | author-supplied, but the AI can offer a proposal to accept/edit |
| A | AI-generated by `expand` (proposals); author accepts or edits |
| D | **derived** — computed from other slots, never stored, never authored |
| **R** | **required for render** — the book cannot render until this is filled + accepted |

## 2. The node envelope (every node, every kind)

```jsonc
{
  "id": "n_a3f",              // 'n_…' stable id (client-minted)
  "book_id": 1169,
  "parent_id": "n_root",     // tree edge
  "level": 5,                // 0..5 ladder depth; entities carry their pillar's level+ (see §4)
  "kind": "scene",           // §3 ladder | §4 entity
  "position": 2,             // order among siblings (reading order falls out of this, §6)

  "content": { /* kind-specific — §3 / §4 */ },

  "authoring": {
    "source": "ai_then_user",  // user | ai | ai_then_user — who wrote the CURRENT content
    "locked": false,           // ★ pin → hard constraint downstream; regen never overwrites
    "status": "accepted",      // empty | proposed | draft | accepted
    "src_hash": "a91f",        // hash of this node's INPUT SET when last generated (§ staleness)
    "prose_src_hash": "7c2e"   // scenes only — hash of the scene plan the prose was written from
  },

  "proposals": [ { "id":"p1", "content":{} } ],   // AI options to choose among (the ease lever)
  "chosen": "p1"
}
```

`status` lifecycle: `empty` (slot exists, unfilled) → `proposed` (AI offered options) → `draft` (content
set, not signed off) → `accepted` (locked into the ladder; unlocks children's `expand`). `locked` is
orthogonal — an accepted node the author pins so regeneration can never touch it.

## 3. The ladder kinds

The vertical narrative chain. `content` shapes, field by field.

### L0 `seed`
| field | type | fill | |
|---|---|---|---|
| logline | string | ★/A | one sentence; the idea, or pick a proposal |

### L1 `premise`
| field | type | fill | |
|---|---|---|---|
| genre | string[] | U/A | |
| tone | string[] | U/A | |
| dramatic_question | string | ★/A | the yes/no the book answers |
| shape | `{ setup, turn1, turn2, turn3, resolution }` (5 strings) | ★ | steer the turns + ending |

### L2 `pillar` (the hub — also parents the entity branch, §4)
| field | type | fill | |
|---|---|---|---|
| controlling_idea | string | ★/A | the argument the whole book proves |
| ending | string | ★ | the pinned target the structure must reach |

### L3 `movement` (×3–5; acts)
| field | type | fill | |
|---|---|---|---|
| title | string | A | optional label |
| goal | string | A/U | what this movement drives at |
| turning_point | string | ★ | place the turn — the act's hinge |
| value | `{ name, from, to }` | A/U | the value-charge shift across the movement |

### L4 `beat` (×~3 per movement; the causal skeleton — always its own row)
| field | type | fill | |
|---|---|---|---|
| summary | string | A/U | one line |
| connector | `therefore` \| `but` | A/U | causal link to the prior beat (first beat exempt) |
| threads | `[{ id, promise, kind:setup\|payoff\|advance }]` | ★/A | which promises this beat plants/pays; author picks what matters |

### L5 `scene` (the leaf — owns its prose; **R** for render)
| field | type | fill | |
|---|---|---|---|
| pov | ref→`character` | A/U | defaults from `narration.default_pov` |
| loc | string | A/U | where |
| time | `{ when, elapsed }` | A | story-clock stamp |
| present | ref[]→`character` | A/U | who's on stage |
| goal | string | A/U | scene-level want |
| conflict | string | A/U | what opposes it |
| outcome | string | A/U | how it resolves (usually a "no, and…" / "yes, but…") |
| value_shift | `{ value, from, to }` | ★/A **R-soft** | **must be non-empty** (no flat "and-then" scenes) |
| advances | `[{ ref:<thread\|relationship id>, how }]` | A | what this scene moves |
| realizes_tentpole | ref→`tentpole` \| null | A/U | the set-piece this scene delivers, if any |
| chapter_start | `{ title, pov?, epigraph? }` \| null | U/A | **partition boundary** — non-null = a chapter begins here (§6) |
| prose | `{ text, words }` | A→★ **R** | the actual words; AI writes, author does voice corrections |

## 4. The entity kinds (the cast/world branch off `pillar`)

Foundations, as nodes. Same envelope, same four verbs. They **do not render**; they constrain
generation and are referenced by id from scenes/beats (§5).

### `character` (← `foundations.cast`)
| field | type | fill | |
|---|---|---|---|
| name | string | U/A | |
| role | `protagonist`\|`antagonist`\|`ally`\|`love_interest`\|`minor` | U | exactly one `protagonist` |
| want | string | A/U | the conscious goal |
| need | string | ★ | what they actually need |
| wound | string | ★ | the backstory injury — AI can't guess |
| lie | string | ★ | the false belief the wound installed |
| truth | string | A/U | what dismantles the lie |
| idiolect | string | A/U | how they speak — feeds prose voice |
| tag | string | A | a recurring identifying handle |

### `relationship` (← `foundations.relationships`)
| field | type | fill | |
|---|---|---|---|
| a, b | ref→`character` ×2 | U | the dyad |
| bond | string | A/U | what ties them |
| charge | string | A/U | the current tension/valence (mutated by scenes that `advance` it) |

### `tentpole` (← `foundations.tentpoles`)
| field | type | fill | |
|---|---|---|---|
| summary | string | U/A | the set-piece/obligatory moment |
| *(state)* | `authoring.status` | — | `proposed`=**fluid**, `accepted`=**pinned**; archived=**killed** |

Placement: a tentpole is "placed" when some scene's `realizes_tentpole` references it. A pinned tentpole
with no placement is an open obligation (a lint, §7).

### `world_fact` (← `foundations.world`)
| field | type | fill | |
|---|---|---|---|
| rule | string | U/A | a world law / established fact |
| category | string | A | grouping (magic, politics, tech…) |

## 5. References & integrity

Cross-links (not parent edges) carry a node id; reading order is unaffected by them.

| from → to | field |
|---|---|
| scene → character | `pov`, `present[]` |
| scene → tentpole | `realizes_tentpole` |
| scene → thread/relationship | `advances[].ref` |
| beat → thread | `threads[].id` |
| relationship → character | `a`, `b` |

Integrity rules: a reference must resolve to a live (non-archived) node of the right kind; deleting an
entity nulls dangling refs (never orphans a scene). References are part of a scene's **input set**, so
editing a referenced entity marks the scene stale (§ staleness in spec).

## 6. Derived projections (never stored)

Pure functions of the tree. Recomputed on read; `reconcile` materializes the page rows only.

| projection | definition |
|---|---|
| reading order | depth-first leaf order: movements (by position) → beats → scenes |
| chapters | partition of the scene order by `chapter_start` boundaries → `[{ index, title, pov?, epigraph?, scene_ids[], word_count, est_pages }]` |
| word_count | Σ `scene.prose.words` over a chapter / the book |
| est_pages | `word_count / wpp(layout)` |
| pages | per chapter → a `section` page (title) + a `text` page (its scenes' prose, flowed) — `reconcile`, spec §8 |

## 7. The completeness contract

Two checkable gates. **Generation completeness** governs how far the ladder is built; **render
completeness** is the predicate for "the book exists."

**Per-rung gate (expand order):** a node may be `expand`ed only when its parent is `accepted`. A rung is
"complete" when all its ★/U/**R** fields are filled and `status==accepted`.

**Render predicate — the book renders iff ALL hold:**
- `title`, `author`, `mandate.word_target` set (§1 **R**).
- ≥1 `movement` → ≥1 `beat` → ≥1 `scene` exists.
- **every** scene has `prose.text` non-empty with `status==accepted` (**R**).
- every scene has a non-empty `value_shift`.
- the scene order is partitioned by chapters: the first scene in reading order is a `chapter_start` (else
  a single implicit chapter wraps all scenes).
- every `pinned` tentpole is placed (referenced by some scene) — *warning*, not a hard block.

A partially-filled DNA renders a partial book (only scenes with accepted prose appear) — the structure is
always renderable to *what it has*; "complete" just means every slot that gates render is satisfied.

## 8. The fill map — what the UI must extract (in priority order)

The cognitive load is front-loaded onto the human core and tapers to nudges. The UI's whole job is to
pull the ★ slots from the author and let `expand` fill the rest. Ordered by leverage:

| order | the meaningful ask (★) | rung | why only the human |
|---|---|---|---|
| 1 | logline / dramatic_question | seed/premise | the idea itself |
| 2 | **wound + lie** of the protagonist | character | the emotional core; AI guesses generically |
| 3 | controlling_idea + **ending** | pillar | what the book proves, and where it lands |
| 4 | the **turning points** (shape turns + movement hinges) | premise/movement | the spine's load-bearing reversals |
| 5 | **mandate**: heat (content_type), word_target, success_criteria | settings | the binding contract — laundered away if not pinned |
| 6 | voice_exemplar | settings | the single strongest prose anchor |
| 7 | which **threads** matter; tentpoles to pin/kill | beat/tentpole | author taste over AI's over-seeding |
| 8 | value_shift tweaks, scene order, prose voice corrections | scene | taper — AI does the volume, author nudges |

Everything not marked ★ is AI's to propose and the author's to accept — *choose, don't author*. Everything
marked D the UI only displays. That is the entire interaction surface: **fill the ★, accept the A, watch
the D.**
