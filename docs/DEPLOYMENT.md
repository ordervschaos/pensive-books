# Deployment

See [ADR 0001](adr/0001-public-nextjs-private-spa.md) for *why* the apps are split. This doc covers *how* deploys actually happen.

## Topology

```
pensive-books (this repo, main branch)
├── apps/web/      ─► Vercel project: pensive           ─► app.pensive.me
└── apps/marketing ─► Vercel project: pensive-marketing ─► pensive.me, www.pensive.me
```

Both Vercel projects are connected to this GitHub repo. Each project has a `Root Directory` set to its app folder and an `Ignored Build Step` that skips rebuilds when the commit didn't touch its source.

| Project | Framework | Root Directory | Domain(s) |
|---|---|---|---|
| `pensive` | Vite (SPA) | `apps/web` | `app.pensive.me` |
| `pensive-marketing` | Next.js | `apps/marketing` | `pensive.me`, `www.pensive.me` |

## Normal flow: push to `main`

```bash
git push origin main
```

Vercel evaluates the Ignored Build Step on each project:

- Files in `apps/web/` or `packages/` changed → **`pensive`** builds, **`pensive-marketing`** skips
- Files in `apps/marketing/` or `packages/` changed → opposite
- Both touched → both build; neither touched → both skip

Status shows up in `https://vercel.com/anzalansari-s-team` within seconds.

## Preview deploys (feature branches and PRs)

```bash
git checkout -b feat/foo
git push origin feat/foo
```

Each project creates a preview URL (`pensive-git-feat-foo-*.vercel.app` and `pensive-marketing-git-feat-foo-*.vercel.app`). Open a PR and both URLs appear in the PR checks.

## Manual deploys via CLI

If you need to force a deploy without a commit, run from the app folder so the right project's `.vercel/project.json` is picked up:

```bash
# SPA
vercel --prod --cwd apps/web

# Marketing
vercel --prod --cwd apps/marketing
```

## Rollback

Dashboard: project → Deployments → pick an earlier `READY` deploy → ⋯ → **Promote to Production**.

Or CLI:

```bash
vercel rollback <previous-deployment-url>
```

Each project rolls back independently.

## Project configuration reference

These are the exact settings each project uses; reproduce them if you ever recreate a project from scratch.

### `pensive` (SPA)

| Setting | Value |
|---|---|
| Framework Preset | Vite |
| Root Directory | `apps/web` |
| Build Command | `cd ../.. && corepack pnpm build:web` |
| Output Directory | `dist` (Vite default) |
| Install Command | `cd ../.. && corepack pnpm install --frozen-lockfile` |
| Node.js Version | 22.x |
| Ignored Build Step | `cd ../.. && git diff HEAD^ HEAD --quiet -- apps/web packages` |
| Env (Prod + Dev) | `ENABLE_EXPERIMENTAL_COREPACK=1` |

`apps/web/vercel.json` rewrites all non-asset paths to `/index.html` for client-side routing.

### `pensive-marketing` (Next.js)

| Setting | Value |
|---|---|
| Framework Preset | Next.js (auto-detected) |
| Root Directory | `apps/marketing` |
| Build/Install Commands | Vercel defaults (workspace install handled automatically) |
| Node.js Version | 22.x |
| Ignored Build Step | `cd ../.. && git diff HEAD^ HEAD --quiet -- apps/marketing packages` |
| Env (Prod + Dev) | `ENABLE_EXPERIMENTAL_COREPACK=1`, `PENSIVE_APP_ORIGIN=https://app.pensive.me` |

## DNS

`pensive.me` is registered at a third-party registrar with DNS managed by Squarespace. Records that matter for serving:

| Type | Name | Value |
|---|---|---|
| A | `@` | `76.76.21.21` (Vercel anycast) |
| CNAME | `www` | `cname.vercel-dns.com` |
| CNAME | `app` | `9bd001c54c41ab1f.vercel-dns-017.com` (Vercel per-domain managed target) |

The `app` subdomain uses a CNAME to a unique Vercel hostname instead of the generic `cname.vercel-dns.com`; this was auto-generated by Vercel when the domain was attached and works the same way. Don't replace it with an A record — Squarespace will flag a conflict.

## Gotchas worth knowing

1. **`pnpm-lock.yaml` must match `package.json`.** Don't add deps with `npm install` — it creates a `package-lock.json` and skips the pnpm lockfile, and Vercel's frozen-lockfile install fails. Always use `pnpm add`.
2. **Vercel defaults to pnpm 9** unless `ENABLE_EXPERIMENTAL_COREPACK=1` is set. With it set, Vercel respects `packageManager: pnpm@10.x` in the root `package.json`.
3. **The Ignored Build Step runs from the Root Directory**, not the repo root. That's why the script prepends `cd ../..`.
4. **Don't manually attach a domain to multiple projects.** A domain attached to two projects causes ambiguous routing. Detach from the old project first (dashboard → Settings → Domains → Remove), then attach to the new one.
5. **Avoid `vercel domains rm <domain>`** — it removes the domain from the *team registry* (destructive), not just from a single project. Use the dashboard instead.
