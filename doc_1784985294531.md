# Making the agent rail self-sufficient

**Ship:** every decision the agent puts to the author is now resolvable inside the chat, and the
composer can attach context itself. Two gaps closed; two deliberately left, listed at the bottom.

---

## 1. Where this sits

**Subcontext:** the DNA studio (`/books/:slug/dna/tree`). **Position:** the *review* stage of the
agent loop — the agent has finished a turn and handed something back to the author.

The studio is two surfaces over one substrate (`book_nodes`):

```
                    book_nodes  (the substrate — the single source of truth)
                        │
        ┌───────────────┴───────────────┐
        │                               │
   TREE (spatial)                  RAIL (temporal)
   "where does this live?"        "what just happened?"
   DnaTreePage + Subtree           AgentRail + steps feed
```

Both are **projections**. Neither owns the data. That's the architectural claim; the bug was that
it wasn't true for one class of thing.

## 2. The gap, precisely

The agent hands three kinds of thing back to the author. Before this change:

| What the agent produces | Where it's stored | Where the author resolves it |
|---|---|---|
| a **proposal** (`propose_node_ops`, `propose_expansion`, `propose_prose_render`) | `book_agent_runs.proposals` | ✅ the rail (`ProposalCard`) |
| a **question** (`ask_author`) | `book_agent_runs.pending` | ✅ the rail (`Composer`'s answer card) |
| **staged options** (`propose_options`) | `book_nodes.proposals` | ❌ **the tree only** (`ProposalPicker`) |

Note the storage column. Proposals and questions live on the *run*, so the rail — which projects
the run — got them for free. Options live on the *node*, so only the tree, which projects nodes,
could see them. **The seam followed the storage, not the user's task.** The chat rendered a
"jump to the tree" card instead, which is a UI admitting it can't finish its own sentence.

The second gap was quieter: **attaching context**. The rail's focus tray could only *detach*. To
add an anchor you clicked the `@` icon on a tree row. So even steering the agent's attention
required leaving the conversation.

## 3. What changed

### a. `agentRail/OptionsCard.tsx` — the rail-native twin

The tree's `ProposalPicker` and the new `OptionsCard` are **two renderings of one decision**:

```
        node.proposals  ← agent's propose_options writes here
               │
      ┌────────┴────────┐
      │                 │
ProposalPicker      OptionsCard          ← different chrome
 (tree chrome:       (rail chrome:
  T / MONO / SERIF)   pv-* Tailwind)
      │                 │
      └────────┬────────┘
               │
    lib/dnaProposals.ts                  ← ONE write
    chooseNodeProposal / discardNodeProposals
               │
      describeOps(...)                   ← ONE diff derivation
```

The duplication is **presentational only**. The write and the before→after derivation are shared,
so "use this" means exactly one thing regardless of where it's clicked. This is the same pattern
`ProposalCard`/`ResolvedCard` already use with `DiffRows` — the codebase had the idiom, options
just hadn't been given it.

`AgentRail` now derives `optionNodes = nodes.filter(n => n.proposals?.length)` off the live tree it
already receives — no new subscription, no new state. The "next step" nudge is gated on it too, so
an unresolved choice doesn't get buried under a fresh CTA.

The `plan` step's jump-to-tree card survives, demoted from *the only way* to *"show it in place"*.

### b. `@` mentions in the composer

`Composer` had a slash-command popover hard-wired to `AgentCommand`. It now takes a generic
`ComposerMenu` (`items / hi / setHi / onPick / onEscape`) and `AgentRail` builds whichever menu the
draft calls for. One keyboard handler, two triggers — arrow keys, Enter/Tab, Escape written once.

The trigger regex is `/(^|\s)@([^@\n]*)$/`:
- group 1 is the **word boundary** — so `foo@bar.com` doesn't open a node picker mid-email;
- group 2 may contain spaces, because DNA node labels are prose (`Bram's door`), not handles. A
  query that matches nothing simply closes the menu, so this is self-limiting.
- On pick, `draft.replace(MENTION_RE, "$1")` strips the token and restores the boundary — the
  anchor rides **out-of-band** in `attachedLiveIds`, so leaving the text would double-say it.

## 5. Deliberately left

- **Stale accept/discard** (`staleActions.ts`) — reachable only from the tree row's chip and the
  `FocusPanel`. This is *not* an agent-staged decision; it's tree-computed state (a node's
  `src_hash` no longer matches its inputs). Folding it into the chat would mean inventing a
  "N nodes went stale" card with no conversational occasion. Flagging, not building.
- **Render → pages / Read** — the top-bar `read →` is global chrome, visible on every tab
  including with the tree scrolled away, so it isn't a *tree-only* action today.

If the standard should be "the chat can do literally everything," stale is the next slice and it
needs a design decision about what occasions the card.
