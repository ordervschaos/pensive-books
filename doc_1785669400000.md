# Wired the verify-layer reads into the DNA agent's tool belt

Executed item #1 from `doc_1785668685869.md`'s "what I'd do, in order" — the highest value-to-effort
gap: three read-only diagnostics existed as edge functions wired to UI panels, but the agent itself
couldn't call them. It could act on the book far better than it could perceive it.

## What changed

**`supabase/functions/book-agent/tools.ts`** — three new entries in `THREAD_DNA_TOOLS`:
- `read_shape` — does the acts deliver the premise's promised movements? (no input; whole-book)
- `read_facts` — does this scene's prose contradict the continuity canon before it? (input: scene id)
- `read_confusion` — cold-read the prose so far as a first-time reader; where does it lose the thread?
  (no input; whole book, budget-limited)

**`supabase/functions/book-agent/exec-tools.ts`** — one handler block per tool, added between
`check_against_contract` and `audit_vision` (the existing in-agent judge tools). Each:
1. fetches `book_nodes` via the `service` client (already scoped to `bookId`)
2. reuses a shared pure helper from `_shared/novel-dna.ts` to assemble the read's input:
   - `read_shape` → `buildShapeReadInput(nodes)`
   - `read_facts` → `ledgerBefore(nodes, sceneId)` + `entityRegistryBlock(nodes)`
   - `read_confusion` → `chapters(nodes)`
3. calls the same judge prompt the standalone edge function uses (ported inline, not HTTP-called —
   avoids auth friction since the agent's `service` client has no user JWT)
4. returns a `tool_result` block with a compact text verdict; **no write-back** to `book_nodes` — these
   stay read-only, same invariant as `check_against_contract`/`audit_vision`

## Deliberate simplifications (kept the diff minimal)

- **Model tier**: reused `getRoleModels().agent` (already imported, already the pattern for every other
  in-agent judge) rather than importing `getActiveModels()` fresh to match the standalone functions.
- **`read_facts`**: dropped `value_carrier` (needs a `value_shift` input the agent tool doesn't take)
  and `fingerprint` (structure-miner-only output, not agent-actionable) from the prompt — the agent
  gets facts + contradictions, the part it can act on.
- **`read_confusion`**: the client's UI flow folds a "reader recap" from `authoring.prose_digest.line`
  per scene; that field isn't reliably typed server-side. The tool instead uses a raw-prose tail
  (capped at 3000 chars) as the "what you know so far" recap — the same fallback `confusionRead.ts`
  already uses when a scene has no digest yet. Not a new invention, just the existing fallback path
  made the only path.

## Verification

- `deno check book-agent/exec-tools.ts book-agent/tools.ts` — clean (the only errors reported are a
  pre-existing `EdgeRuntime` global-typing gap in `_shared/task.ts`, reproduced on unmodified files too
  — not introduced by this change).
- Deployed: `supabase functions deploy book-agent`.
- Not yet exercised end-to-end against a live agent thread — next real test is letting the agent call
  these mid-run on an actual book.
