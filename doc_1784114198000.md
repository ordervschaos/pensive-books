# Story-craft web research: B (precompute → craft_notes) + A (inline agent tool)

## What was built

A web-research capability for the DNA story engine, in two layers sharing one core.

### The shared core — `supabase/functions/_shared/research.ts`
`researchCraft({question, context})` → one Anthropic `web_search` call → `{notes, sources}`.
- **Retrieval-augmented generation (RAG):** pulls *non-parametric* knowledge (fresh web text) so the
  writer isn't limited to what the model memorised in training.
- **Anthropic server tool** `web_search_20260209` (dynamic-filtering variant; GA, **no beta header**).
  Anthropic runs the search + citation server-side and returns results in the *same* call — so no
  external search API and no new API key (ANTHROPIC_API_KEY already backs the stack).
- **Provider pinning:** the call uses `claude-opus-4-8`. Even though the active tier is DeepSeek, a bare
  `claude-*` id routes to Anthropic through `llm.ts`: DeepSeek can't serve claude ids (`wireModelFor` →
  null), so `resolveRoute` falls back to the model's native `anthropic` order → the *passthrough* branch,
  which sends the server-tool def to Anthropic unchanged. (The OpenAI-conversion branch would have
  mangled the tool; passthrough avoids it.)
- **Distillation is the whole point.** A raw search for "how to write a vampire hook" returns SEO
  listicle sludge that makes prose *more* clichéd. The system prompt reframes toward *reference/exemplar*
  material (genre conventions, comps, real facts) and ranks by source quality — garbage-in is the risk.

### B — precompute pass: `supabase/functions/dna-research/`
`POST { bookId, question, topic?, context? }` → `researchCraft` → merge into `books.craft_notes` under a
topic key → `{ topic, notes, sources }`. Stateless, like the `read-*` verify fns. Writes ride the existing
`books` row + its Realtime stream — no new table. Research lands **out of the generation hot path**,
author-editable, inspectable before it shapes prose.

### Wiring B into generation — `book-agent/context.ts`
`books.craft_notes` was a **dormant column** (existed since 2026-06-18, referenced only in a docs page,
injected into *nothing*). Now the agent's context assembles a `<craft_notes>` block from it — an
**anchor, not a fence** (fold what's relevant, ignore the rest), matching the DNA agent's context
philosophy. Without this, B would have been inert.

### A — inline tool: `research_web` in `book-agent/tools.ts` + `exec-tools.ts`
A **read-class tool** (modeled on `audit_vision`): the agent calls it mid-turn, it runs `researchCraft`,
returns the distilled brief to the model, **and** persists to `craft_notes` — so A and B converge on the
same store and inline research becomes durable. Batchable, doesn't end the turn; counts toward the
read-run nudge. Reachable the moment the agent judges it needs real-world reference.

## Placement decision (why B is the substrate, A the escalation)
- **B = precomputation/caching:** research ahead of time, inspect/edit, then generation reads notes with
  no live search in the loop — keeps the timeout-sensitive agent loop deterministic.
- **A = on-demand fetch:** reactive, autonomous, but adds latency + tokens to the ~150s-ceilinged turn.
- Both were built; A persists into B's store so nothing is one-shot.
