# Craft Notes tab — per-book overrides of the tier-1 story craft

## What it is (placed: DNA studio → new tab, book-level config)

A new **Craft Notes** tab in the DNA tree studio (`/books/:slug/dna/tree/craft`). It lists every
generation stage that carries distilled story-craft, shows the built-in default, and lets the author
**rewrite that craft per book**. A rewritten note actually changes generation (writer + agent both read it).

## Why it matters

The story-craft rules — how a logline is forged, the premise anatomy, the beat causality/polarity laws,
the scene-direction grammar — were **hard-coded** in the generation prompts. Every book got the same craft.
This exposes those rules as an editable surface with a safe default fallback, so an author can bend the
system's taste to their book without touching code. Without it, "make it write like X" had no home.

## The system (stakeholders, parts, dataflow)

```
 SOURCE OF TRUTH (edge)                 MIRROR (web)                 UI (web)
 _shared/craft-kb.ts  ──lock test──▶  lib/craftNotes.json  ──▶  CraftNotesPane (Craft Notes tab)
   CRAFT_NOTES[] const                 (committed artifact)         edits → books.craft_overrides
   craftBody(key, overrides)                                              │  { craftKey: text }
   craftOverrideBlock(overrides)                                         ▼
        ▲                                                        books.craft_overrides (jsonb)
        │ read at generation time                                        │
        ├── dna-expand  (writer path): ${craftBody(key, craftOver)} in each stage prompt
        └── book-agent/context.ts (agent path): <craft_overrides> block supersedes default-craft skills
```

**Two write paths, one substitution point.** Generation is split: the **writer** (`dna-expand`) renders
the actual content per stage; the **agent** (`book-agent`) plans/edits and drives the writer. Both had the
craft baked in. Now:
- `dna-expand` swaps each `${LOGLINE_CRAFT}`-style literal for `${craftBody("logline", craftOver)}` —
  returns the override if the author set (and didn't blank) one, else the code default.
- `book-agent/context.ts` injects a `<craft_overrides>` block (`craftOverrideBlock`) listing only the
  overridden stages, told to supersede the default craft embedded in the agent's skills. This reaches the
  agent per-book without touching the static skill bodies.

## Key architectural terms (vocabulary)

- **Tier-1 / tier-2 craft** — tier-1 = immutable system craft in code (`craft-kb.ts`); tier-2 = the
  author's per-book override. This tab is the tier-2 editor. (The pre-existing model in memory.)
- **Source of truth + committed mirror + lock test** — the same pattern as `dnaSchema.ts` ↔
  `dna-schema.json`. Edge `CRAFT_NOTES` is canonical; `craftNotes.json` is a committed copy the web reads at
  runtime (can't import across the deploy boundary); `craftNotes.artifact.test.ts` fails if they drift.
  Regenerate with `UPDATE_CRAFT_NOTES=1 npx vitest run craftNotes.artifact`.
- **Deploy-boundary seam** — web (Vite) and edge (Deno) can't share a folder; the mirror bridges them.
- **Fallback-on-blank** — an override with empty/whitespace text is stripped on save, so clearing a field
  reverts to the code default rather than storing `""` (which would read as "customized").
- **Column separation** — stored in a NEW `books.craft_overrides` jsonb, deliberately **not**
  `books.craft_notes` (which is the distilled web-research `{ topic: note }` map — a different concern).

## Deliberate boundaries (what I did NOT do)

- The **judges** (`read-logline`, `read-premise`) still ground on the tier-1 default, not the override —
  they're the objective bar, so a bad author note can't rubber-stamp itself. Generation bends; judging holds.
- Only the **5 stages that actually carry distilled craft** are listed (logline, premise, beats·causality,
  beats·polarity, scene·direction). Node kinds with no craft slot (act, character, world_fact…) aren't shown
  — an empty editor for them would have no generation effect (speculative).
