# The agent as guide — greet, teach, offer (2026-07-10)

## Where this sits
The **AgentRail** (the studio's single agent surface) + the **guided journey**
(`dnaJourney.ts`) + the agent's **system prompt** (`book-agent` edge fn). Three
layers of the same stance: the agent is not just an executor, it's a *guide*
that teaches the craft ladder as it walks you down it.

## What shipped

### 1. The greeting (client, zero-cost) — `AgentRail.tsx`
When the chat is empty, the rail no longer shows generic "talk to the agent"
copy. It now renders a **journey-aware scripted greeting**:

- **Orientation**: "I'll walk you from your brief to finished prose, one rung
  at a time — idea → foundations → structure → scenes → prose."
- **Teach block** (`STEP_TEACH`): 1–2 plain sentences on the *current* rung's
  concept — what a logline IS, why the premise must carry a price, why beats
  are "therefore/but" and never "and then". Keyed by the same substep key as
  `STEP_RECIPE`, so it can never point at a different rung than the agent is
  driving.
- **No idea yet?** (`needsIdea` = seed step + empty `briefIdea(brief)`): the
  greeting switches to ideation stance ("tell me a genre, a feeling, or a
  scene you can't shake — or let me pitch directions") and the next-step card
  becomes **"Find the story idea — pitch me a few directions"**, sending an
  ideation ask (`IDEA_MESSAGE`) instead of "generate logline options".

Because the greeting shows *whenever the thread is empty*, it also re-teaches
correctly mid-journey (a "New chat" at the beats stage teaches beats, not
loglines).

### 2. The offer (existing machinery, re-aimed)
The **next-step nudge card** was already the CTA; one click sends the real
agent turn. This is the "offer to propose a few options" — the AI call happens
on *acceptance*, not on page open.

### 3. The persona (server) — `book-agent` SYSTEM_THREAD, deployed
New **"## Teach as you go"** section: the first time a rung comes up in a
chat, the agent opens with 1–2 plain sentences (what + why) before acting;
defines each craft term on first use; never lectures or re-explains; and when
there's no idea, interviews lightly or pitches 3–4 directions in prose before
shaping a logline.

## The design fork (surfaced, decided)
**Scripted greeting + click-to-accept** vs **auto-fired real agent turn** on
page open. Chose scripted because:
- your own phrasing — "explain what a logline is and **offer** to propose" —
  is exactly greet-then-offer;
- an auto-fired turn costs an AI call per fresh open, sits silent 5–15s
  before greeting, and risks double-fires across tabs;
- the scripted copy is deterministic and instant, and the *teaching duty* is
  duplicated into the prompt so the agent keeps guiding after turn one.

If you later want the agent to literally speak first (a real generated
greeting), the safe shape is a one-shot kickoff message guarded by
`steps.length === 0 && sessionCount === 0` + a per-book localStorage latch —
the pieces exist; it's a small addition on top of this.

## Architectural terms in play
- **Empty-state onboarding** — the UI pattern of using a blank surface to
  orient and teach instead of showing nothing.
- **State-derived wizard** — the journey isn't a stored step counter; the
  current rung is *derived* from the tree every render (`currentObjective`),
  so the greeting/nudge/agent can never disagree with reality.
- **Progressive disclosure** — teach one concept at the moment it becomes
  relevant, not the whole ladder upfront.
- **Persona prompting / system prompt** — behavior shipped as prompt text
  (the teach-as-you-go stance) vs shipped as code (the scripted greeting);
  this feature deliberately uses both, with the free layer first.
- **CTA (call to action)** — the nudge card; the greeting's "offer".
