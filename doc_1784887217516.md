# A simple eval: brief → logline

**What this is.** A single-turn evaluation harness for the first refinement step in the DNA ladder — turning
the author's raw `brief.idea` into a polished **logline**. Built by applying `knowledgebase/agents/eval.md`
(Anthropic's "How to evaluate AI agents") to one narrow, well-specified capability.

## Where it sits

- **System under test (SUT):** the *deployed* `dna-expand` edge fn, `target: "logline"`. We grade the real
  production path — real prompt bytes, real provider (the `ai_provider` switch), logged to `ai_calls`. No local
  prompt mirror (project memory: `eval-bridge` drift is a known trap).
- **Grader stack** (the eval doc's three grader types, combined — a *hybrid* score):
  1. **Code-based** (`deterministicChecks`): shape rules (≤2 sentences, no label/quotes/JSON, not a verbatim
     restate via Jaccard token-overlap) + per-task `must_mention` / `must_avoid` regexes (distinctive-element
     survival). Fast, cheap, objective.
  2. **Model-based** (`read-logline`, the deployed judge): the `LOGLINE_CRAFT` axes (idea_fidelity,
     genre_tone_fit, originality_honored, stakes_grounded), 1–5 each. Captures nuance a regex can't.
  3. **Tracked metrics:** tokens / latency / provider read back from `ai_calls` via the returned `callId`.
- **Scoring:** *binary* pass (all graders must pass) for the headline number; axis means give the
  *partial-credit* view. Two non-determinism metrics: **pass@1** (per-trial rate) and **pass^k** (all k trials pass).

## The task suite (`scripts/eval-logline-tasks.json`)

8 tasks, deliberately **balanced** (eval doc Step 3 — one-sided evals cause one-sided optimization):
- rich vs minimal briefs (haunted-chatbot vs idea-only-minimal),
- genre/heat/audience mandates (romcom comedy, explicit dark-romance, middle-grade),
- an **anti-inflation** task (quiet-literary) whose `must_avoid` checks the forge does **not** invent thriller
  stakes for a quiet story,
- originality-survival (memory-tax: "taxes paid in memories" must appear explicitly).

Every task ships a **reference solution** — a known-good logline that must pass all graders. `--refs` mode grades
those instead of generating, proving tasks are *solvable* and graders are *fair* before trusting a live score.

## What the eval caught (the point of evals)

Running it surfaced **three real production bugs**, none of which unit tests would have found:

1. **Provider outage.** `ai_provider = "auto"` routed `deepseek/deepseek-v4-pro` to **MuleRouter first**, whose
   balance is **negative** → every live AI call was 402-failing. Fixed by setting the switch to `deepseek`
   (DeepSeek's own API — the PM-intended host). *This was a full production outage the eval exposed on call one.*
2. **Logline forge truncation.** The forge called with `max_tokens: 400` and **no effort bound**. DeepSeek-v4-pro
   is a *reasoning model* whose thinking tokens count **inside** `max_tokens`; at default-high effort it burned the
   whole 400 on hidden reasoning and returned an **empty string** (`stop_reason: max_tokens`). Fix: `effort: "low"`
   + `max_tokens: 3000` — mirrors what the `read-logline` judge already did.
3. **Judge truncation.** Same bug class in the grader: `read-logline` at `max_tokens: 1200` truncated its 4-axis
   JSON mid-array (`Unexpected end of JSON input`). Bumped to 3000.

## Result

24/24 pass@1 (3 trials × 8 tasks), all tasks pass^3, mean axis 4.42–5.00. The path went from **100% broken →
100% green**. The suite is now effectively a **regression eval** (eval doc Step 7: a saturated eval tracks
drift, not capability). heist-stolen-art is the hardest task (lowest mean, 4.42; one earlier run scored
idea_fidelity=2) — the natural next "hill to climb" if we want a capability signal.

## Run it

```
node scripts/eval-logline.mjs                 # 8 tasks × 2 trials, live
node scripts/eval-logline.mjs --trials 3      # pass@1 vs pass^k spread
node scripts/eval-logline.mjs --refs          # grade the reference solutions (fairness check)
node scripts/eval-logline.mjs --only memory-tax --keep
```

Transcripts → `scripts/.eval-logline.jsonl`; report → `scripts/.eval-logline-report.md` (both gitignored).
